# 后端维护脚本风险索引

`apps/api/scripts/` 中的文件主要是一次性初始化、历史数据修复、定向删除和生成工具，不是日常开发命令集合。除 OpenAPI 生成流程外，本目录脚本默认都应视为“需要专项审阅和明确授权”的运维工具。

特别说明：`deploy-production.sh`、`bootstrap-linux.sh`、`init-db.mjs`、所有 seed、backfill、clear 和 delete 脚本均不是推荐的日常命令。看到脚本名或 package script 并不代表可以直接运行。

## 风险等级

| 等级 | 含义 | 默认动作 |
|---|---|---|
| L1 生成副作用 | 主要写本地生成文件，原则上不应改业务数据 | 核对输入、输出和工作树后按流程运行 |
| L2 定向数据写入 | 会创建或更新一类既有数据，没有完整 dry-run | 需明确授权、备份和副本演练 |
| L3 广泛初始化/覆盖 | 会批量新增、upsert 或覆盖系统配置、账号、业务数据 | 仅专项初始化；禁止对未知或生产库直接运行 |
| L4 破坏性 | 会清库、硬删除记录或绕过正常业务状态机 | 默认禁止；必须逐次明确授权并验证可恢复性 |

本表只描述当前源码可见行为。脚本可能继续演变，执行前必须重新阅读脚本和本次 diff。

## 脚本清单

| 脚本 | 等级 | 当前行为与主要风险 |
|---|---:|---|
| `generate-openapi.mjs` | L1 | 从构建后的 Nest 应用生成 `apps/api/openapi.json`；会实例化应用模块，可能初始化数据库、Redis、队列或定时器连接，并覆盖 OpenAPI 文件 |
| `backfill-assets.mjs` | L2 | 扫描本地 `uploads/`，读取文件并向 `FileAsset` 创建记录；运行目录错误会扫描错误位置，且没有 dry-run |
| `backfill-orders.mjs` | L2 | 分批遍历并更新所有订单的履约、评价和删除标记字段；属于订单高风险域，没有 dry-run 或自动回滚方案 |
| `bootstrap-seed.mjs` | L3 | upsert 系统标签、角色、等级和管理员数据；会覆盖既有管理员字段，不是无害的“补缺”脚本 |
| `production-seed.mjs` | L3 | upsert 生产基础数据、管理员和站点设置；重复运行也可能覆盖线上配置 |
| `demo-seed.mjs` | L3 | 创建演示会员、车辆、商品、账号和流水；仅可用于可丢弃的隔离数据库，部分数据不是幂等的 |
| `seed.mjs` | L3 | 写入管理员、商品、券、演示会员和集团等多域数据；不是生产初始化标准流程 |
| `bootstrap-linux.sh` | L3 | 生成 Prisma Client、执行 migration；失败时会 fallback 到 `db push`，随后运行 bootstrap seed。该 fallback 可能掩盖迁移失败，禁止作为通用部署入口 |
| `init-db.mjs` | L3 | 以高权限数据库连接创建库、用户并授权；源码中还遗留了硬编码连接信息。不得运行或复制其中值，应先完成凭据轮换和脚本重构 |
| `deploy-production.sh` | L4 | 旧版“生产部署”脚本会强制 reset 数据库后 seed；还混用 npm/pnpm 假设和已过时 Prisma 参数。它是遗留危险脚本，不是可用部署方案 |
| `clear-file-assets.mjs` | L4 | 无真实交互确认即删除全部 `FileBinding` 和 `FileAsset` 记录，但不删除磁盘文件，会造成数据库与磁盘状态分离 |
| `delete-order.mjs` | L4 | 跨多个订单关联表硬删除指定订单并解除部分关联，绕过正常取消、退款、权益回收和审计状态机 |
| `delete-queue-item.mjs` | L4 | 硬删除队列项及任务；`--force` 可绕过默认状态限制，可能破坏订单/队列审计链 |

## 执行前的强制条件

对任何 L2、L3 或 L4 脚本，以下条件缺一不可：

1. 用户在当前会话明确授权了脚本名、目的和目标环境；过去的笼统授权不能复用。
2. 执行前检查 `git status --short` 和脚本 diff，确认没有覆盖用户正在修改的脚本。
3. 解析并核对脱敏后的数据库主机、端口、库名和环境；不得在终端输出或回复中暴露完整连接串。
4. 已完成数据库备份，并实际验证备份可以恢复；仅“已创建备份文件”不够。
5. 先在最新生产副本或隔离数据库演练，记录预估影响行数、耗时、锁和副作用。
6. 对没有 dry-run 的脚本，先用只读查询核对目标记录；不能靠运行后日志来发现选错库或选错 ID。
7. 高风险域操作需要维护窗口、停止相关写流量，并准备明确的回滚或恢复步骤。
8. 执行后核对业务不变量、审计流水、关联记录和应用日志，而不只看进程退出码。

没有满足这些条件时，应停止并向用户说明缺失项，不能自动降级到更危险的命令。

## 明确禁止的替代方案

- migration 失败时禁止自动运行 `prisma db push`、reset 或清库重建。
- 禁止把 seed 当作“补配置”工具在生产反复运行。
- 禁止用 delete 脚本替代订单取消、退款、队列移除等正式业务接口。
- 禁止在生产执行 demo seed、任意 clear 脚本或带强制选项的删除脚本。
- 禁止因为有数据库备份就跳过副本演练、目标确认和影响评估。
- 禁止复制脚本内遗留的账号、密码或连接信息到 README、`.env.example`、聊天或日志。

## OpenAPI 生成

当且仅当后端接口、DTO 或 Swagger 契约发生变化时，使用仓库标准流程：

```bash
pnpm -F WashClubAPI run openapi
pnpm generate:client
```

第一条命令会先构建后端并覆盖 `apps/api/openapi.json`；第二条会覆盖 `packages/api-client/src/generated/**`。运行前后都应检查工作树，并审阅生成 diff。若 SDK 响应被生成为 `void`，应补后端响应 DTO/Swagger 声明后重新生成，不能手改生成文件。

## 推荐的数据库发布原则

本目录目前没有可以无条件推荐的生产一键部署脚本。可靠流程应由独立 runbook 或 CI/CD 明确实现，至少包含：

- 锁定依赖并构建可重复的制品；
- 审阅、备份并在副本验证 migration；
- 仅执行待应用的 `prisma migrate deploy`，不 reset、不 fallback 到 `db push`；
- 显式运行 Prisma Client generate；
- 健康检查、关键业务冒烟和失败恢复步骤；
- 生产凭据由安全的环境注入，不存在于脚本或文档中。

在该流程建立并验证前，Codex 不应把遗留 shell/seed 脚本包装成新的“一键部署”。

## 日常开发可以做什么

- 阅读脚本、审计行为和编写改进方案。
- 在不连接数据库的前提下构建后端或生成 Prisma Client。
- 在接口契约变化后，按上一节生成并审阅 OpenAPI/SDK。
- 需要数据修复时，优先新增带 dry-run、显式目标、影响统计、幂等设计和审计记录的专用工具；仍需经过上述授权流程。

任何实际数据库写入都遵守根 [`AGENTS.md`](../../../AGENTS.md) 的数据库和高风险业务规则。
